# Синхронизация с плеером и телефоном: часть 1 — устройство-как-диск

Дата: 2026-10-14. Статус: одобрено пользователем (части 1–4 дизайна в разговоре; дальше «делай сам»).

## Зачем

Музыка из библиотеки Sonicache должна попадать на плеер, SD-карту или Android-телефон в режиме
накопителя без ручного копирования: подключил, отметил что нужно, увидел, что изменится, нажал одну
кнопку.

Это первая из четырёх частей. Остальные получат свои спецификации:

| # | Часть | Связь |
|---|---|---|
| 1 | **Ядро + устройство-как-диск** (эта) | папка на съёмном диске или любая выбранная папка |
| 2 | Android по кабелю | MTP через Windows Portable Devices |
| 3 | iPhone и Android по Wi-Fi | библиотека по сети (Subsonic/WebDAV) |
| 4 | Старый iPod | iTunesDB; iPod с Rockbox — уже часть 1 |

## Решения пользователя

- Выбор как в iTunes: отдельные **плейлисты, альбомы, исполнители** или **вся библиотека**;
  выбор помнится для каждого устройства.
- Программа пишет и удаляет **только в своей папке** `Sonicache/` на устройстве; чужие файлы не трогает.
- Файлы копируются **как есть**; для устройства можно включить **пережатие в MP3**.
- Запуск **по кнопке**, перед этим **предпросмотр**: сколько добавится, уберётся, влезет ли.

Допущения: синхронизация в одну сторону (библиотека → устройство); плейлисты кладутся как `.m3u8`.

## Компоненты

### `sonicache/engine/devices.py` — логика без интерфейса

- `Device`: `id`, `name`, `root`, `free`, `total`, `kind` (`"drive"` или `"folder"`).
- `find_devices(folders)` — съёмные диски и добавленные вручную папки.
  - Windows: `GetLogicalDrives` → `GetDriveTypeW == DRIVE_REMOVABLE` → `GetVolumeInformationW`
    (метка, серийный номер). Диск без носителя (картридер без карты) пропускается.
  - macOS/Linux: подпапки `/Volumes`, `/media/<user>`, `/run/media/<user>`, кроме системного тома.
  - `id` диска — `vol:<серийный номер>`, `id` папки — `folder:<sha1 пути>[:12]`.
  - Список дисков берётся из `_drives()`, которую тесты подменяют.
- `Source(path, rel, duration)` — файл библиотеки, его путь внутри `Sonicache/` (POSIX, относительный)
  и длительность для оценки размера после пережатия.
- `PlaylistSpec(name, sources)` — плейлист как список путей исходников.
- `plan(root, sources, playlists, transcode, bitrate, can_transcode) -> Plan`.
- `run(root, plan, ffmpeg, progress, stop) -> Report`.

### Список «что наше» — на устройстве

`<корень>/Sonicache/.sonicache-sync.json`:

```json
{"version": 1,
 "files": {"Sonicache/Radiohead/In Rainbows/01 15 Step.mp3":
           {"source": "C:\\Music\\Radiohead\\In Rainbows\\01 15 Step.flac",
            "size": 31234567, "mtime_ns": 1700000000000000000, "mode": "mp3:256", "bytes": 7654321}}}
```

`mode`: `copy`, `mp3:<битрейт>` или `playlist`. Удаляется только то, что есть в `files`.
Нечитаемый или незнакомый список считается пустым (в журнал — предупреждение): тогда ничего не удаляется.

### Выбор — на компьютере

`devices.json` в папке данных программы:

```json
{"folders": ["D:\\Phone\\Music"],
 "devices": {"vol:1A2B3C4D": {"name": "WALKMAN",
   "selection": {"all": false, "playlists": ["mix"], "albums": ["C:\\Music\\Radiohead\\In Rainbows"],
                 "artists": ["radiohead"], "transcode": false, "bitrate": 256}}}}
```

Исполнители хранятся в нижнем регистре, как ключи `libraryArtists()` в окне.

### Методы `gui.Api`

| Метод | Что делает |
|---|---|
| `devices()` | подключённые устройства и добавленные папки, с выбором и признаком `synced` |
| `add_device_folder()` | диалог выбора папки, запоминает её |
| `forget_device_folder(id)` | убирает добавленную вручную папку из списка |
| `save_device(id, selection)` | сохраняет выбор |
| `device_plan(id)` | предпросмотр: числа для строки и кнопки |
| `sync_device(id)` | запускает синхронизацию в фоне; `False`, если одна уже идёт |
| `stop_sync()` | останавливает после текущего файла |

События в `poll()`: `{"type": "sync", "state": "running", "device", "done", "total", "title"}`, затем
`{"type": "sync", "state": "done" | "stopped" | "error", "device", "copied", "deleted", "failed",
"conflicts", "error"}`.

## Что попадает в набор

Набор собирает `gui` (там библиотека и плейлисты), движок получает готовый список `Source`:

- «Вся библиотека» — все файлы всех записей библиотеки и все плейлисты;
- иначе — объединение: файлы отмеченных альбомов (`folders.album_files`, одиночный трек — сам файл),
  все записи отмеченных исполнителей, треки отмеченных плейлистов (включая «Недавние» и «Чаще всего»);
- повторы убираются по пути исходника; пропавшие исходники не попадают в набор и считаются в `missing`.

`rel` — путь файла относительно той папки библиотеки, в которой он лежит, под `Sonicache/`.

## Раскладка на устройстве

- Музыка: `Sonicache/<rel>`. Каждая часть пути очищается под FAT32/exFAT: `<>:"/\|?*` и управляющие
  символы → `_`, точки и пробелы в конце убираются, часть не длиннее 120 символов, весь путь — 240.
- При пережатии расширение становится `.mp3`. Если два исходника легли на одно имя (`a.flac` и `a.mp3`),
  второй получает ` (2)`.
- Рядом с треками копируются спутники: обложка папки (`folders.cover_file`) и `.lrc` трека, режим `copy`.
- Плейлисты: `Sonicache/Playlists/<имя>.m3u8`, пути относительные, через `/`, только треки из набора.

## Разница и порядок работы

Для каждого нужного файла:

| Состояние | Действие |
|---|---|
| есть в списке, исходник тот же (размер и `mtime_ns`), режим тот же, файл на месте | оставить |
| есть в списке, но исходник или режим изменились, или файла нет | записать заново |
| нет в списке, по этому пути ничего нет | записать |
| нет в списке, по этому пути лежит чужой файл | не трогать, `conflicts` |

Всё, что есть в списке и не нужно, удаляется.

`run`:

1. Удаляет оставшиеся `*.part` в `Sonicache/` от прерванного запуска.
2. Удаления — сначала, чтобы освободить место; затем убирает опустевшие папки внутри `Sonicache/`.
3. Запись по одному файлу: в `<имя>.part`, затем `os.replace`. Пережатие — свой вызов ffmpeg
   (`libmp3lame`, `-b:a <битрейт>k`, `-ar 44100`, `-map 0:a:0 -map 0:v? -c:v copy`, `-map_metadata 0`,
   `-id3v2_version 3`), теги и обложка сохраняются, исходник не трогается. Исходник в mp3 копируется
   как есть и при включённом пережатии.
4. Плейлисты пишутся, если их текст изменился.
5. Список сохраняется после удалений, каждые 20 файлов и в конце (в `finally`), атомарно через `.tmp`.

Остановка проверяется между файлами; идущий ffmpeg завершается.

## Место

`need = Σ размеров записываемого − Σ bytes удаляемого и перезаписываемого`. Размер копии — размер
исходника; размер после пережатия — `длительность × битрейт / 8 + 64 КБ` (теги и обложка).
`fits = need <= free`. Если не влезает, кнопка неактивна, а строка говорит, сколько не хватает.

## Интерфейс

- **Боковая панель библиотеки:** под плейлистами заголовок «Устройства», устройства (имя и свободное
  место), «+ Выбрать папку». Пока открыта библиотека, список обновляется раз в 3 секунды.
- **Страница устройства** — третья страница в `#library-page`, рядом со страницами альбома и исполнителя:
  - шапка: имя, путь, полоса места (занято / свободно) и строка «свободно X из Y»;
  - «Вся библиотека» — флажок; без него — три раскрывающихся списка с флажками:
    **Плейлисты, Исполнители, Альбомы**, у альбомов и исполнителей поле фильтра;
  - «Пережимать в MP3» и битрейт (128/192/256/320); без ffmpeg — неактивно, с подсказкой;
  - строка предпросмотра: «Добавится 134 трека (8,4 ГБ) · уберётся 12 · после синхронизации
    свободно 5,1 ГБ», или «Не хватает 2,3 ГБ»;
  - кнопка «Синхронизировать»; во время работы — «Остановить»;
  - у добавленной вручную папки — кнопка «Убрать из списка».
- Выбор сохраняется сам; предпросмотр пересчитывается через 300 мс после изменения.
- **Прогресс** — в строке над библиотекой, как у «Дописать теги»: «Синхронизация: 34 из 210 · название ·
  не отключайте устройство». По окончании — итог на 30 секунд и в `announce()`.
- Иконка устройства — пока `i-folder`: иконки Phosphor для устройства и USB нужно скачать отдельно.

## Ошибки

- Устройство отключили, диск заполнился (`OSError` на записи в устройство) — остановка, список
  сохраняется, `state: "error"` с понятным текстом; следующий запуск продолжит.
- Исходник не читается или ffmpeg не справился — файл в `failed`, работа идёт дальше.
- Одновременно идёт одна синхронизация.

## Не входит в эту часть

Автозапуск при подключении, пункт «Синхронизировать с…» в контекстных меню, синхронизация в обратную
сторону, MTP, сеть, iPod.
