# Синхронизация с плеером и телефоном: часть 2 — Android по кабелю (MTP)

Дата: 2026-10-14. Продолжает [часть 1](2026-10-14-device-sync-design.md): правила выбора, предпросмотр,
список «что наше» и раскладка `Sonicache/` остаются теми же. Пользователь попросил делать без
согласований; решения ниже приняты по ходу и перечислены в отчёте.

## Зачем

Android-телефон по кабелю в обычном режиме («Передача файлов») подключается по MTP, и Windows не даёт
ему буквы диска: часть 1 его не видит. Нужно, чтобы такой телефон появлялся в разделе «Устройства»
рядом с дисками и синхронизировался той же кнопкой.

## Что выяснено о системе

- В программе COM уже вызывается напрямую через `ctypes` по таблицам методов (`thumbbar.py`,
  `mediacontrols.py`); ни comtypes, ни pywin32 в зависимостях нет. Часть 2 делает так же: **новых
  зависимостей нет**.
- Номера методов WPD сняты из библиотек типов самой Windows (`PortableDeviceApi.dll`,
  `PortableDeviceTypes.dll`), а GUID и ключи свойств сверены с байтами системных DLL. Ничего не взято
  по памяти без проверки, кроме методов `IPortableDeviceDataStream`, которые поэтому не используются.
- WPD показывает и обычные флешки (`MSC`) и iPhone (`PTP`, только фото): берутся только устройства с
  протоколом `MTP` (`WPD_DEVICE_PROTOCOL`).

## Архитектура

### Цель записи (`Target`) — в `devices.py`

`plan()` и `run()` части 1 работают с путями на диске. Они переходят на объект «куда пишем» с
небольшим набором действий; пути везде — `/`-строки от корня цели (`Sonicache/...`).

| Метод | Что делает |
|---|---|
| `free() -> int` | свободное место |
| `exists(dest) -> bool`, `is_file(dest) -> bool` | есть ли что-то по пути / файл ли это |
| `read_bytes(dest) -> bytes` | содержимое файла (`FileNotFoundError`, если нет) |
| `write_bytes(dest, data)` | файл целиком, заменяя прежний |
| `put(local, dest) -> int` | копия локального файла, заменяя прежний; размер записанного |
| `delete(dest)` | удалить файл, если он есть |
| `prune(folder)` | убрать опустевшие папки от `folder` вверх, но не выше `Sonicache/` |
| `clean_parts()` | убрать недописанные `*.part` внутри `Sonicache/` |

- `DriveTarget(root)` — прежнее поведение: `.part` и `os.replace`, атомарный список.
- `plan(root, …)`, `run(root, …)`, `load_manifest(root)`, `save_manifest(root, …)` принимают `Path`
  (как раньше; оборачивается в `DriveTarget`) или готовую цель.
- Пережатие в mp3 идёт во временный файл на компьютере, затем `put()` — одинаково для всех целей.
- Ошибка чтения **исходника** — `failed` этого файла; любая другая ошибка цели — конец синхронизации
  (как в части 1).

### MTP — новый модуль `sonicache/engine/mtp.py`

Два слоя, чтобы логику путей можно было проверить без телефона:

1. **`_Wpd`** — тонкая обёртка над COM WPD через `ctypes` (только Windows): открыть устройство,
   перечислить детей папки (`id`, имя, папка ли, размер), создать папку, записать файл потоком,
   переименовать, удалить объект, прочитать файл, свободное место и ёмкость хранилища.
2. **`MtpTarget(session, storage_id, base="Music")`** — `Target` поверх этого: путь → объект через
   перечисление детей (кэш на папку, сбрасывается после записи и удаления), создание недостающих
   папок, запись через `<имя>.part` и переименование (если устройство не умеет переименовывать —
   удалить старое и записать сразу под именем). Наши файлы на телефоне лежат в **`Music/Sonicache`**
   хранилища: там их ищут плееры, и корень телефона не засоряется.

`find_storages()` — подключённые MTP-устройства и их хранилища (внутренняя память, SD-карта): имя
устройства, описание хранилища, свободно/всего, постоянный id. Устройство без хранилищ (телефон
заблокирован или в режиме «Только зарядка») тоже возвращается, с пометкой «не готово».

Результаты кэшируются на 15 секунд по PnP-id: окно спрашивает список каждые 3 секунды, а открытие
телефона по MTP дорогое.

### Устройства в `devices.py` и окне

- `Device` получает поле `note` (почему устройство не готово; пусто — готово); `kind` теперь
  `drive`, `folder` или `mtp`.
- `id` хранилища: `mtp:<sha1(PnP-id + постоянный id хранилища)>[:12]`; имя:
  `«<имя телефона> · <описание хранилища>»`; `root` — служебная строка, по которой собирается цель.
- `devices.target(device)` — цель для устройства: `DriveTarget` или `MtpTarget`.
- `find_devices()` добавляет хранилища MTP после дисков и перед папками.
- `gui.py` везде берёт цель через `devices.target(device)`, не `Path(device.root)`.
- Окно: у MTP вместо пути показывается «По кабелю · папка Music/Sonicache», кнопки «Открыть папку»
  нет. У неготового устройства — его пометка вместо предпросмотра («Разблокируйте телефон и выберите
  в уведомлении «Передача файлов»»), кнопка синхронизации неактивна.

## Ошибки

- Телефон отключили или он заблокировался посреди записи — ошибка COM на цели → синхронизация
  останавливается, список сохраняется (если ещё можно), следующий запуск продолжает: недописанный
  `*.part` убирается.
- Список «что наше» на телефоне читается и проверяется так же, как на диске (пути только внутри
  `Sonicache/`).
- Без Windows (`sys.platform != "win32"`) MTP-устройств просто нет.

## Тесты

- `tests/test_devices.py`: существующие тесты части 1 проходят через `DriveTarget` без изменений;
  те же сценарии `plan`/`run` прогоняются на `MtpTarget` поверх поддельного `_Wpd` в памяти
  (новые файлы, повторный запуск, удаление только своего, остановка и продолжение, `.part`,
  переименование не поддерживается, плейлисты, список «что наше»).
- `tests/test_mtp.py`: `MtpTarget` на поддельном `_Wpd` — разрешение путей и кэш, создание папок,
  замена файла, `prune`, `clean_parts`; COM-обёртка на этой машине без телефона —
  `PortableDeviceValues` (строка, GUID, число туда и обратно), коллекции ключей и значений,
  `find_storages()` возвращает список.
- Ручная проверка с настоящим телефоном описана в README (раздел про устройства).

## Не входит

Wi-Fi и iPhone (часть 3), iPod (часть 4), чтение тегов и обложек с телефона, синхронизация в обратную
сторону.
